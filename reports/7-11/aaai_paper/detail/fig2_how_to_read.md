## 1. 这张图在问什么

这是全文的核心实验。论文主张"往 latent world model 里注入物理量没用",Figure 2 就是那个证据。

- **每一行** = 一种注入物理的方式(钉住位置、加速度写成 a=g、probe 软监督……共 10 种)
- **每一列** = 一个物理场景(匀速运动 / 抛体 / 碰撞)
- **每一格** = 「用了这种注入」的误差 ÷ 「什么都不注入」的误差

```
1.30×  →  注入后误差是原来的 1.30 倍,变差 30%
0.79×  →  注入后误差降到 0.79 倍,变好
1.00×  →  没区别
```

暖色 = 变差,蓝色 = 变好。**整张图几乎全是暖色,这就是"注入没用"的证据。**

## 2. 斜纹是什么意思

一句话:

> **斜纹 = 这格的三个种子和基线的三个种子混在一起,分不出差别。**
> **实心 = 每一次实验都比基线差(或好),差异是真的。**

### 为什么需要这个区分

同一个配置跑两遍,结果不一样 —— 数据怎么切分、样本喂入顺序、GPU 浮点累加顺序都带随机性。所以哪怕什么都不改,重跑一次误差也会变。

因此每格跑 3 遍(种子 3072/1234/42),基线也跑 3 遍。每格不是一个数,而是**三个数**。

### 一个直观例子

碰撞列的两个格子,它们共用同一个基线:

```
        误差(nMSE)越往右越差 →
        0.36                                                      0.70
        -----------------------------------------------------------------
不注入         B                  B         B                        ['0.393','0.495','0.548']

probe                                                    X XX        ['0.647','0.660','0.664']
        → 三个 X 全在三个 B 右边,完全不重叠 = 确实更差   ⇒ 实心

freeMLP                          X     X   X                         ['0.529','0.560','0.583']
        → X 和 B 交错在一起,分不清                       ⇒ 斜纹
```

**probe**:哪怕运气最好的那次 probe(0.647),也比运气最差的那次基线(0.548)还差。真效应。

**freeMLP**:基线自己三次就在 0.393–0.548 之间晃,freeMLP 的三次(0.529–0.583)正落在这个范围里外。均值算出来 1.16×,写在纸上像"误差涨了 16%",但**基线自己重跑就能差 39%**,16% 淹没在里面。换个种子完全可能反过来。

### 判据(代码里的实现)

```python
worse_sep  = min(该格三个值) > max(基线三个值)   # 全在基线之上 → 实心暖
better_sep = max(该格三个值) < min(基线三个值)   # 全在基线之下 → 实心蓝
# 两者都不成立 → 斜纹(噪声内)
```

注意这个判据**必须双向**。曾经只写了 `worse_sep` 一个方向,导致唯一那个真增益(低于基线)被误判成"未分离"而画上斜纹,和 caption 说的 "the one solid blue cell" 矛盾。已修(commit `5505638`)。

## 3. 为什么旧版(单种子)图不需要斜纹

**不是不需要,是没资格画。** 单种子每格只有一个数,拿不出任何波动信息,只能把比值印上去、默认读者当它是真的。

代价是实打实的:旧图上 **11 个看着"注入更差"的格子,补种子后发现其实分不出差别**。

## 4. 这张图现在能读出三件事

1. **几乎全是暖色** → 27 格里 26 格不优于基线(15 实心更差 + 12 噪声内)
2. **17 个实心暖格** → 确凿有害,不是运气
3. **唯一一个实心蓝格**(`+velocity` / parabola,0.79×)→ 全图唯一真增益

第 3 点支撑正文那句"唯一的例外是机制的 signature,不是可用的先验":它只在抛体域有效(那里速度是可外推的驱动量),换到 uniform 和 collision 就反向变差。**要求事先知道每个域的动力学、且跨域反号的先验,是诊断工具不是方法。**

注意:图上有**两个**蓝格。另一个是 `probe+slot` / parabola 的 0.81×,但它带斜纹 —— 抽样 0.072–0.127 与基线 0.115–0.127 重叠,不是真增益。**"唯一"能立住,正是因为斜纹把它标掉了。** 没有斜纹的话图上就是两个蓝格,这句话没法说。

## 6. 两处已知问题(待决定)

### a) `[dyn] strict a=g` 与 `[free] grounded` 是同一个配置

两者的 `config.yaml` 全量逐字段比对**完全相同**(只差 run 名),所以表里两行数字一模一样。

不是跑错了,是设计空间里两条论证线撞在同一点:

```
label-free :  structured=0.0  +  dynamics(const)
   ↓ 加真标签(这就是 grounded 的定义)
grounded   :  structured=1.0  +  dynamics(const)  ←┐
                                                    ├ 完全一样
a=g        :  structured=1.0  +  dynamics(const)  ←┘
```

dinowm 那边同样如此(两个 run 名就叫 `grounded_const` 和 `grounded2_const`,后者名字里的 "2" 即"第二遍")。

**当前处理**:保留两行、填同值,在 caption 和附录表注明它们是同一配置。摘要的 "ten variants" / "29 of 30" 不动。

**若改为合并**:9 行 × 3 域 = 27 格,统计变成 15 实心更差 / 11 斜纹 / 1 更好 = **26 of 27**。要同步改摘要("nine variants")、§4.1 标题、intro、结论共 5–6 处。

> 注意 `label-free` 和 `grounded` **不是**重复(前者 `structured=0.0`,后者 `1.0`),所以"有无标签"这条对照臂完好,合并不会破坏它。

### b) Table 1 里 `grounded` 标成 *soft* 是错的

该配置 `consistency.weight=0`、`probe.weight=0`,没有任何软辅助损失;只有 `structured`(论文自己定义为 hard)和 `dynamics`(架构硬约束)。按论文 caption 自己的定义应为 **hard**。内部报告 `physics_injection_full_scan.md` 也归类为"硬·演化·有标签"。尚未改。
